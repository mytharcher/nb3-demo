版本：V1.3

日期：2026年10月28日

需求对象：六步骤投稿、AI评分、评分复议及方法论应用门户

## 1. 需求概述

公司以“任务执行六步骤”指导专项工作，专项完成后以PPT形式投稿并参与评审。本需求说明定义系统需支持的用户、业务流程、功能、权限和统计口径，作为业务确认及后续产品设计、研发实施的需求依据。

系统应提供统一投稿入口，串联直属上级审核、AI评分、评分确认或异议复议，并建设六步骤知识门户和投稿看板。投稿清单旧页面停用，投稿查询、评分及复议结果统一从投稿记录进入。

## 2. 业务目标

1. 统一管理六步骤专项成果的提交、审核、评分和复议过程。
2. 依据已发布的评分规则版本生成结构化、可解释、可追溯的AI评分结果。
3. 支持投稿人对具体评分项提出异议，并由三位专家完成复议。
4. 集中展示六步骤方法论、优秀案例、激励规则和学习资源。
5. 提供按投稿月份筛选的投稿和评分统计，支持业务总结与推广。

## 3. 用户角色与权限

| 角色           | 职责                                                           | 权限范围                                                                           |
| -------------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 投稿人/员工    | 提交投稿、查看本人投稿和评分、确认评分或发起异议、确认复议结果 | 仅查看本人投稿及其审核、评分和复议记录；可编辑退回修改的记录并重新提交             |
| 投稿人直属上级 | 审核下属提交的六步骤投稿                                       | 查看并处理本人管理范围内的待审核投稿；填写审核意见、通过或退回                     |
| 六步骤管理员   | 管理评分标准和门户内容，分配专家，查看和处理流程异常           | 查看全部投稿、评分及复议；维护标准、模板、案例、激励和学习资源；为复议分配三位专家 |
| 六步骤评审专家 | 处理管理员分配的复议任务                                       | 仅查看分配给自己的复议任务；对复议评分项逐项评分或不予受理并提交评论               |
| 系统           | 执行AI评分、通知、状态流转和超时自动确认                       | 按配置执行自动任务，并记录处理时间和执行结果                                       |

系统应结合角色与组织关系控制数据范围。投稿人不得查看他人投稿；专家不得查看未分配给自己的复议任务；关键操作需记录操作人和时间。

## 4. 信息架构

左侧导航至少包含以下模块：

6. 任务执行六步骤介绍：理念、核心步骤、方法论、发展历程。
7. 投稿：新增投稿、本人投稿及评分、模板下载。
8. 优秀案例：按部门、年份展示获奖案例，支持在线查看或下载。
9. 激励规则：月度激励、终审激励。
10. 投稿情况看板：展示投稿和评分统计。
11. 学习中心：赋能课程、常用工具、评分规则及德智平台学习入口。

投稿记录页同时承载投稿查询、评分查看和复议结果查看。直属上级和专家可通过待办或相应工作台进入待处理记录。

## 5. 投稿及评分业务流程

### 5.1 新增投稿与上级审核

12. 投稿人进入投稿记录页面，点击“新增投稿”，系统打开右侧滑窗。
13. 投稿人填写投稿名称、投稿人、投稿部门、汇报人、投稿月份、备注等信息并上传六步骤PPT。可从账号和组织架构带出投稿人、部门和直属上级。
14. 投稿人点击“确认投稿”后，系统保存记录并将状态设为“审核中”，通知直属上级。
15. 直属上级查看投稿信息及PPT，填写审核意见并选择通过或退回。退回必须填写原因。
16. 审核通过后，系统触发AI评分。审核退回后，投稿人编辑原记录并重新提交；每次提交生成新的文件版本，保留历史文件及提交记录。

### 5.2 AI评分与投稿人确认

17. AI按投稿审核通过时适用的已发布评分标准版本评分，记录所用版本。
18. 系统保存总分及逐评分项的结构化评分结果，至少包括评分项、得分、评分依据；具备能力时记录对应PPT页码或证据位置。
19. AI评分成功后，投稿状态改为“评分完毕”，系统通知投稿人查看评分。
20. 投稿人可查看总分及各项评分依据，并选择：

- 确认评分：投稿状态改为“完成”。
- 发起异议：选择一条或多条评分项，逐项填写异议原因并提交，投稿状态改为“评分复议中”。

21. AI评分失败时，系统记录失败状态及原因并通知管理员；管理员可发起重试。失败记录不得显示为正式评分完成。

### 5.3 评分异议与专家复议

22. 投稿人可一次选择多条评分项提出异议；每条所选评分项均须填写异议原因。原始AI评分及依据需保留。
23. 投稿人提交后，系统通知六步骤管理员。
24. 管理员为该投稿分配三位不同的评审专家并发出通知。管理员可查看处理进度。
25. 每位专家对每个待复议评分项选择“二次评分”或“不予受理”，并填写复议评论后提交。二次评分需在该评分项允许的范围内。
26. 三位专家均完成处理后，投稿状态改为“复议完成”，系统通知投稿人查看复议结果。
27. 投稿人可查看异议原因、原评分、专家处理方式、复议评论、复议分数及最终分数，并确认复议结果。确认后状态改为“完成”。
28. 复议完成后三个工作日内未确认，系统自动确认复议结果并将投稿状态改为“完成”，记录截止时间和自动确认时间。

### 5.4 高分/低分自动复议

29. AI总分低于30分或高于85分时，系统自动创建复议并通知管理员分配专家；30分和85分本身不触发。
30. 自动创建的复议覆盖该投稿的全部评分项，不要求投稿人逐项提出异议。
31. 后续分配、专家处理、复议结果确认及超时自动确认流程与普通复议一致。
32. 三位专家完成后直接通知投稿人，不设置管理员最终审核节点。

## 6. 功能需求

### 6.1 评分标准管理

管理员可上传、查看和维护《六步骤评分规则》《任务执行六步骤评分规则讲解》等材料。系统应支持将评分规则结构化为AI可使用的配置，至少包括：

- 标准版本、名称、状态、生效时间、发布人及发布时间；
- 评分维度和评分项名称；
- 评分项权重或分值、分值范围及单位；
- 评分说明、判定条件、证据要求；
- 原始规则文件及结构化规则的关联。

管理员应能校正结构化解析内容、预览规则并校验后发布。已发布版本不得被覆盖；规则变更应生成新版本。历史投稿评分继续关联原使用版本，不因新版本发布而改变。

### 6.2 投稿记录页面

- 提供新增投稿入口、投稿记录查询和详情查看。
- 支持按投稿名称、部门、投稿人、汇报人、投稿月份、提交时间范围、状态和分数筛选。
- 每页默认显示10行，支持分页。
- 列表展示投稿名称、部门、投稿人、汇报人、投稿月份、提交时间、状态和总分。
- 点击记录可查看投稿信息、当前及历史PPT版本、审核意见、评分依据、异议原因和复议结果。
- 投稿人仅查看本人记录；直属上级查看管理范围记录；管理员查看全部记录。
- 页面提供投稿模板下载入口。文件格式、大小限制和是否允许多个附件由系统配置确定。

### 6.3 专家复议工作台

- 专家默认查看状态为待本人处理且分配给自己的复议任务。
- 详情展示投稿信息、PPT、原评分、评分依据及投稿人异议原因（如有）。
- 专家须逐项选择“二次评分”或“不予受理”，录入复议分数或说明，并填写复议评论后提交。
- 专家只能提交本人被分配的任务；提交后处理记录锁定。
- 管理员可分配或调整三位专家、查看复议进度；调整需留痕。

### 6.4 复议分数计算

对每个评分项分别计算：

- 选择“二次评分”的专家分数取算术平均；
- 选择“不予受理”的专家不参与该项平均；
- 若三位专家对该项均选择“不予受理”，该项最终分沿用原AI评分；
- 投稿最终复议总分依据评分标准配置的汇总方式计算。

分数有效范围、小数精度和汇总/取整规则应与正式评分标准一致。若标准文件未定义，应在正式发布前由业务补充配置。

### 6.5 通知与待办

系统需在以下节点通知相关人员：新投稿待审核、投稿退回、审核通过并启动评分、AI评分完成或失败、投稿人待确认评分、管理员待分配专家、专家待复议、三位专家全部完成、投稿人待确认复议、超时自动确认。

通知使用公司现有站内通知或待办能力，并提供可直达相关记录的入口。系统记录通知对象、时间及发送结果。实际通知渠道以系统接入能力为准。

### 6.6 六步骤介绍

页面标题：“任务执行六步骤介绍 \| 任务海茫茫 六步骤领航”。突出“一次性把事情做好”，说明六步骤是覆盖任务明确到复盘迭代全流程的系统化方法论，强调全过程管理和闭环思维。

六步骤以流程卡片展示：

| 步骤     | 展示内容                                                          |
| -------- | ----------------------------------------------------------------- |
| 任务明确 | 背景介绍、5W2H分析，结合SMART原则、ABCD法则，确保目标清晰可落地。 |
| 组织执行 | 定职、定责、定任务，使用组织结构图、RACI模型明确责任分工。        |
| 方案有效 | 差距分析、方案制定、可行性评估，建立汇报机制和沟通路径。          |
| 计划清晰 | 制定计划表或甘特图，明确节点、责任人、时间和输出物。              |
| 结果可测 | 通过量化指标佐证目标达成，确保任务输出与计划逻辑对应。            |
| 复盘迭代 | 通过复盘报告、AAR总结经验，沉淀可复用的SOP和流程。                |

发展历程以时间轴展示：

| 年份 | 阶段         | 阶段描述                                                         |
| ---- | ------------ | ---------------------------------------------------------------- |
| 2020 | 专项开启     | 正式启动六步骤专项，梳理专项规划，奠定方法论基础。               |
| 2021 | 专项优化     | 建立规范化六步骤报告，制定评审标准和评审机制。                   |
| 2022 | 聚焦投稿数量 | 上线赋能课程，新增OA审批流程，举办首届年度终审活动。             |
| 2023 | 聚焦投稿质量 | 开展部门内部交流活动，上线常用工具课程，举办初评规则共识会。     |
| 2024 | 量质共进     | 召开主管共识会，优化通用模板，开展定制化培训，举办六步骤文化节。 |
| 2025 | 落地执行     | 组织会议待办“任务明确”评审，确保任务发布合规。                   |

### 6.7 优秀案例

展示不同部门、年份的高分及终审获奖案例，至少包含案例名称、获奖等级、部门、姓名、年份和在线查看/下载入口。初始案例为：2024年一等奖“增加早餐服务六步法”，作者谢金桃。案例资料和附件由管理员维护。

### 6.8 激励规则

分为“月度激励”和“终审激励”，表格展示奖项、数量、金额和获奖规则。奖项信息及规则由管理员维护；具体金额、名额和评选细则由业务提供。

### 6.9 学习中心

展示赋能课程、常用工具、评分规则等资源卡片。课程和工具提供德智平台学习入口；评分规则支持查看当前有效版本及讲解材料。资源链接由管理员维护。

### 6.10 投稿情况看板

看板标题为“六步骤投稿看板”，标题后展示标语“任务海茫茫，六步骤领航”。支持按投稿月份筛选。经业务确认，看板只统计已评分投稿，未评分、审核中或评分中的投稿不纳入指标。

| 指标           | 统计口径                                        | 展示内容                                       |
| -------------- | ----------------------------------------------- | ---------------------------------------------- |
| 总投稿         | 筛选范围内已评分的投稿份数                      | 总份数                                         |
| 投稿平均分     | 已评分投稿总分之和 ÷ 已评分投稿份数             | 平均分                                         |
| 通过率         | 总分大于等于60分的已评分投稿数 ÷ 已评分投稿总数 | 百分比；分母为0时显示“—”                       |
| 部门均分       | 部门已评分投稿总分之和 ÷ 该部门已评分投稿份数   | 按均分从高到低展示部门、投稿份数、均分和通过率 |
| 高分报告Top 10 | 按总分从高到低选取前10份已评分投稿              | 投稿名称、投稿部门、分数                       |

看板随月份筛选联动。用户可见数据应遵守角色数据权限；部门统计及个人信息的展示范围由业务确定。

## 7. 数据记录要求

系统至少需要保存以下业务数据：

| 数据对象       | 主要内容                                                                               |
| -------------- | -------------------------------------------------------------------------------------- |
| 投稿记录       | 投稿名称、投稿人、部门、汇报人、投稿月份、状态、当前总分、直属上级、提交时间及确认时间 |
| 投稿文件版本   | 文件名、文件地址、版本号、上传人、上传时间及对应提交批次；历史版本不可被新文件覆盖     |
| 评分标准及版本 | 源文件、标准版本、生效时间、评分项、分值/权重、判定条件及发布信息                      |
| 评分记录       | 投稿、评分项、AI得分、评分依据、证据位置、使用的标准版本及异议原因                     |
| 专家复议记录   | 复议投稿、专家、评分项、处理方式、复议分数、评论及提交时间                             |
| 流程和通知记录 | 流程节点、状态变化、处理人、意见、操作时间、通知对象和发送结果                         |
| 门户内容       | 六步骤介绍、案例、激励规则、课程/工具资源及链接                                        |

原始AI评分、评分依据、标准版本、投稿文件版本和专家意见应保留，支持追溯。关键业务记录不得因规则更新而覆盖历史结果。

## 8. 状态定义

| 状态       | 说明                               | 后续状态               |
| ---------- | ---------------------------------- | ---------------------- |
| 审核中     | 投稿已提交，等待直属上级处理       | 评分中、退回修改       |
| 退回修改   | 上级已退回，等待投稿人修改         | 审核中                 |
| 评分中     | 上级已通过，AI正在评分             | 评分完毕、评分失败     |
| 评分失败   | AI评分未成功                       | 管理员重试后进入评分中 |
| 评分完毕   | 已生成评分，等待确认或复议         | 完成、评分复议中       |
| 评分复议中 | 异议或自动复议已创建，等待专家处理 | 复议完成               |
| 复议完成   | 三位专家均已提交，等待投稿人确认   | 完成                   |
| 完成       | 投稿人确认，或系统超时自动确认     | 终态                   |

系统应记录状态变化的触发人、时间和原因。AI评分失败、复议待分配等异常信息可作为子状态或流程标记展示，避免主状态含义混淆。

## 9. 业务规则与非功能要求

33. 每次AI评分须关联一个确定的已发布评分标准版本。
34. 投稿文件、评分依据、异议原因和复议意见均应可追溯；退回重提不覆盖历史文件。
35. AI评分可异步执行，页面明确展示处理中、完成或失败状态。
36. 同一投稿的三位专家必须为不同人员；三位专家均提交后复议方可完成。
37. 三个工作日按公司统一工作日历计算；系统记录复议确认截止时间和自动确认时间。
38. 投稿记录与复议列表默认每页10条，按权限提供筛选和查询。
39. 文件类型、大小、预览及安全检查遵循公司文件平台标准，具体配置上线前确认。
40. 站内通知、待办、组织架构及直属上级关系需使用公司现有服务或完成接入。
41. 系统需具备权限控制、审计日志、异步任务失败记录及重复操作防护。

## 10. 主要验收标准

42. 投稿人能通过右侧滑窗提交PPT，投稿记录进入“审核中”，直属上级收到待办。
43. 直属上级能审核管理范围内的记录；退回必须填写原因；投稿人可编辑原记录重提且历史文件版本保留。
44. 审核通过后能触发AI评分；评分完成后保存总分、逐项评分和依据及使用的规则版本。
45. 投稿人能查看本人评分，确认后投稿完成；也能多选评分项并逐项填写异议原因后提交。
46. 总分低于30分或高于85分时自动创建覆盖全部评分项的复议并通知管理员；30分和85分不触发。
47. 管理员能分配三位不同专家；专家只能处理自己的任务，并对所有复议项提交处理方式和评论。
48. 复议分数按已确认规则逐项计算；三位专家完成后直接通知投稿人，无管理员终审节点。
49. 投稿人确认复议后流程完成；三个工作日未确认时系统自动确认并留痕。
50. 投稿记录和复议工作台支持筛选、分页，每页默认10条，且符合数据权限。
51. 看板按投稿月份筛选，只统计已评分投稿，指标按本需求定义计算。
52. 管理员能维护评分标准版本和门户内容；评分标准更新不修改历史评分。

## 12. 根据投稿管理办法补充的需求

本节依据《JST-SS-WI-102A 任务执行六步骤投稿管理办法》（版本A，生效日期2025年12月12日）补充，并已按业务逐项确认。红色文字为本轮新增/修订内容。本节作为确认后的需求基线，优先于前文任何与之不一致的描述。

### 12.1 管理范围、报告撰写人与代投稿

系统适用于公司各部门的任务执行六步骤投稿。全体员工均可作为报告撰写人/投稿人。允许委托他人代为提交，系统必须分别记录实际提交人和报告撰写人/投稿人。实际提交人和报告撰写人均可查看评分、确认评分、发起异议及确认复议结果；每次操作均记录实际操作账号、身份和时间。

### 12.2 投稿报告内容要求

投稿报告应使用最新版模板，并覆盖任务执行六步骤全部内容。提交页面需提供最新模板入口和六步骤内容完整性提示。提示用于帮助投稿人自查，不据此自动判定报告质量或自动拒绝投稿。

| 步骤     | 报告内容要求                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 任务明确 | 包含背景介绍和任务定义表。背景说明问题点、内部环境和外部环境；任务定义遵循ABCD原则并以一句话概括，列明时间安排、负责人、费用预算和预期输出等关键信息。 |
| 组织执行 | 从定职、定责、定任务三个方面说明组织执行安排。                                                                                                         |
| 方案有效 | 包含开展思路和汇报机制。开展思路体现差距分析、初始解决路径、方案升级/选择和最终方案；汇报机制列明阶段、频率/形式、汇报对象及汇报内容。                 |
| 计划清晰 | 计划完整、全面、有逻辑；列明任务名称、直接责任人（DRI）、时间节点和计划输出物，可使用计划表或甘特图。                                                  |
| 结果可测 | 说明原定目标是否达成，并体现结果/输出与计划之间的逻辑关联。                                                                                            |
| 复盘迭代 | 通过复盘报告、AAR等总结任务；说明经验是否提取和固化，以及相关表单、SOP/流程文件、流程上线、宣导或培训等沉淀结果。                                      |

### 12.3 投稿周期与截止时间

常规投稿截止时间为每月最后一天，系统在截止后关闭当月常规投稿。年度活动的投稿截止时间由六步骤管理员根据活动通知配置。页面应展示当前投稿周期、截止时间和提交状态。逾期补交需由管理员另行处理，系统保留审批/操作记录。

### 12.4 确认后的审核、评分和复议流程

系统替代管理办法中现行的OA投稿及审批流程；投稿、上级审核、AI评分、异议复议和结果管理均在新系统完成，不将OA作为投稿或审批主流程。

六步骤专项组中的指定成员担任六步骤管理员。系统不单独设置常规“大众评委”评分角色，常规初评由AI完成。评审专家承担人工复议和AI失败后的人工评分职责。

直属上级审核通过后，AI直接对投稿进行常规评分。总分低于30分或高于85分时，六步骤管理员分配三位专家进行复议；专家处理后按已确认的复议规则计算结果。低于30分和高于85分的自动复议覆盖全部评分项。

AI评分失败时，系统先自动重试。自动重试仍失败后，管理员可手动重新触发AI评分；手动触发仍失败时，管理员可选择三位专家进行人工评分。人工兜底评分时，三位专家分别给出投稿总分，系统取三人总分的算术平均作为最终分数。

对于投稿人发起的异议，三位专家仍按评分项分别选择二次评分或不予受理：选择二次评分的专家分数取平均；不予受理者不参与平均；若该评分项三人均不予受理，则沿用原AI评分。复议完成后直接通知投稿人，不设管理员最终审核节点。

### 12.5 结果公示与档案保存

系统保留次月邮件公示最终评分结果的要求。邮件发送前必须由六步骤管理员审核确认；管理员在发送前填写/确定收件范围。邮件至少包含投稿名称、投稿人/部门、最终分数和获奖信息。系统应保留邮件内容、收件范围、确认人、发送时间和发送结果。

投稿文件、文件版本、审核记录、AI评分及依据、专家复议记录、通知、公示邮件及相关业务资料全部保存在新系统中并长期保存。管理办法所列公示邮件模板编号为JST-SS-WI-102A-001，原文件保存地点为秘书课；系统应提供该模板的电子化维护和使用入口。

## 13. 已确认的差异处理结论

| 主题           | 确认后的需求                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| OA与新系统     | 新系统替代OA投稿及审批流程，业务流程以新系统为准。                                                      |
| 常规评分方式   | AI承担常规初评，不设置常规大众评委评分环节。                                                            |
| 专项组与管理员 | 专项组指定成员担任六步骤管理员。                                                                        |
| 人工评审角色   | 评审专家用于投稿异议复议，以及AI持续失败时的人工兜底评分。                                              |
| 低分/高分处理  | 总分低于30分或高于85分时，管理员分配三位专家复议全部评分项。                                            |
| AI评分失败处理 | 系统自动重试；仍失败时管理员手动重触发；再次失败时可转三位专家人工评分，三人分别给出总分并取平均。      |
| 投稿周期       | 每月最后一天截止常规投稿；年度截止时间由管理员按活动通知配置。                                          |
| 代投稿         | 允许代投稿，分别记录实际提交人和报告撰写人；二者均可进行评分确认和异议操作，并记录实际操作者。          |
| 结果公示       | 保留次月邮件公示；发送前由管理员确认并填写收件范围；邮件显示投稿名称、投稿人/部门、最终分数和获奖信息。 |
| 数据保存       | 投稿及评审相关资料全部保存在新系统并长期保存。                                                          |

### 13.1 上线配置事项

上线前需提供正式评分规则、投稿模板、邮件公示模板及获奖信息字段；由管理员配置年度投稿截止时间、邮件收件范围和获奖信息。AI自动重试的次数及间隔属于系统运行参数，实施时需由产品和技术团队制定可配置策略，并在AI持续失败后开放管理员手动重触发和专家兜底评分。
