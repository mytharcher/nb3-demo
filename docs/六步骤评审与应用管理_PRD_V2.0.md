## 1. 产品概述

### 1.1 背景

公司以“任务执行六步骤”指导专项工作。专项完成后，员工提交PPT报告进行评分和评审。现有管理办法基于OA流程组织投稿、人工评委评分、专项组审核和邮件公示。经业务确认，新系统替代现行OA投稿及审批流程，常规评分由AI完成，并保留专家复议、AI评分失败兜底、管理员确认公示和长期档案保存。

### 1.2 产品目标

- 为员工提供六步骤专项报告的统一投稿和进度查询入口。
- 以AI完成常规评分，并使评分结果关联评分标准版本、评分项和评分依据。
- 为低分/高分投稿、投稿人异议和AI故障提供明确的人工处理闭环。
- 统一维护投稿模板、评分规则、案例、激励与学习资源。
- 以月度看板和经管理员确认的邮件公示支持业务运营。

### 1.3 成功标准

| 目标           | 可验证结果                                                         |
| -------------- | ------------------------------------------------------------------ |
| 流程闭环       | 投稿可追踪至完成状态；审核、AI评分、复议、确认/自动确认均有记录。  |
| 评分可解释     | 每条AI结果包含总分、评分项得分、依据和所用标准版本。               |
| 异常可处理     | AI失败自动重试，管理员可手动重触发，连续失败可转三位专家人工评分。 |
| 业务管理可执行 | 按月截止投稿；年度截止可配置；管理员可确认并发送次月公示邮件。     |
| 知识资源统一   | 门户展示方法论、案例、激励、模板和学习资源。                       |

## 4. 业务流程与状态

### 4.1 常规投稿与AI评分

1. 投稿人或代投稿人填写投稿信息、选择报告撰写人/投稿人并上传PPT，确认后记录进入“审核中”。
2. 系统按撰写人/投稿人组织关系生成直属上级待办；上级检查真实性、完整性、规范性及六步骤要求符合度。
3. 上级通过后，系统将记录进入“评分中”并触发AI评分。上级退回时必须填写原因；投稿人可编辑原记录并重新提交，系统保存新文件版本及旧版本。
4. AI按当前适用的已发布评分标准版本生成逐项评分、依据及总分。评分成功后，系统先判断自动复议条件，再确定投稿状态，并通知报告撰写人和实际提交人。
5. 如总分低于30分或高于85分，系统直接将投稿从“评分中”转为“评分复议中”，自动创建覆盖全部评分项的复议实例，初始处理阶段为“待分配专家”，并通知管理员分配三位不同专家；不经过可供确认的“评分完毕”状态。报告撰写人和实际提交人均不得确认原AI评分或另行发起异议。
6. 如无自动复议条件（总分大于等于30分且小于等于85分），投稿进入“评分完毕”，报告撰写人/实际提交人可确认评分，或对一条/多条评分项提出异议并填写原因。
7. 异议提交后管理员分配三位不同专家；三位专家完成后进入“复议完成”，通知报告撰写人和提交人确认。
8. 投稿人/提交人确认后进入“完成”。复议完成后三个工作日未确认，系统自动确认并记录。

### 4.2 AI评分失败处理

9. AI评分失败时，系统记录失败原因、处理建议及每次尝试的状态、时间和错误信息。网络超时、AI服务暂时不可用等可恢复故障按配置策略自动重试；文件损坏、评分规则缺失等需人工修复的问题暂停评分并通知相应责任人，条件修复后重新触发。
10. 自动重试仍失败时，系统通知管理员，并开放管理员手动重新触发AI评分。
11. 管理员手动触发仍失败时，管理员可指派三位不同专家对该投稿进行人工评分。
12. 三位专家分别给出投稿总分；系统计算三人总分的算术平均作为最终总分，并保存每位专家原始分数、意见和提交时间。该结果作为最终评分，通知报告撰写人和实际提交人确认；不再开放评分异议。
13. 人工兜底评分不应与“对AI评分提出异议的逐项复议”混淆；系统记录其发起原因为AI评分失败。人工兜底分数进入“评分完毕”状态并提供确认操作，但不提供再次发起评分异议的入口。

AI自动重试的次数及间隔尚未确定，作为系统可配置参数由产品/技术方案确定。达到自动重试策略上限后进入管理员待处理。

#### 4.2.1 失败判定与处理边界

AI评分失败是指系统未能生成并保存一份完整、符合评分规则的有效结果，不代表报告得分低。失败及处理边界如下：

| 情况                           | 判定与处理                                                                                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件无法读取或关键内容无法解析 | 包括文件损坏、加密、附件不可访问等。暂停评分，通知管理员协调投稿人/实际提交人或技术人员修复；恢复可读后重新触发。不得将无法读取的内容直接认定为报告缺项并扣分。 |
| 评分规则缺失或无效             | 无适用的已发布版本，或规则配置不完整时暂停评分，通知管理员补充或修正规则；条件满足后重新触发。                                                                  |
| AI服务调用失败                 | 网络超时、服务暂时不可用、限流等可恢复故障按配置自动重试；超过策略上限后按本节流程进入管理员处理。                                                              |
| AI输出不合格                   | 缺少必需评分项、评分依据或总分，返回内容无法解析，或得分超出规则范围时，不采用为正式结果，记录原因并按配置重试。                                                |
| 评分结果不一致                 | 总分与明细不符合规则规定的汇总/取整方式，或结果引用的文件版本、标准版本与任务不一致时，拒绝作为有效评分，记录原因并交管理员排查；修复后重新触发。               |
| 有效结果保存失败               | AI已生成有效结果但保存失败时，优先恢复保存，避免重复调用AI；恢复过程不得重复生成正式评分或重复通知。持续失败时通知管理员处理。                                  |

报告内容缺失或质量差，只要材料可正常读取且评分规则支持判断，应依据规则评分并说明依据，不单独构成评分失败。总分低于30分或高于85分属于评分成功，按规则进入自动复议；30分和85分本身不触发。PPT页码或证据位置属于具备能力时提供的可选信息，缺少该信息不单独构成失败，逐项评分依据仍为必需。

失败记录不得显示为正式评分完成。系统应向有权处理的人员展示失败原因和下一步操作。文件或规则问题须先修复，不能通过反复重试或转人工评分绕过必要条件；可恢复故障及无效输出在自动重试、管理员手动重触发后仍失败时，可按4.2节转三位专家人工兜底评分。

### 4.3 复议专家评分规则

- 专家任务须分配给三位不同专家；仅允许本人处理已分配任务。
- 异议复议按评分项处理。专家对每个复议项选择“二次评分”或“不予受理”，填写评论；二次评分必须在评分项分值范围内。
- 单项复议最终分：所有“二次评分”分数取算术平均；“不予受理”不参与平均；三位专家均不予受理时沿用原AI分。
- 低于30分或高于85分自动复议覆盖全部评分项。该阈值仅判断AI初评结果；专家复议结果及AI失败后的人工兜底结果即使仍低于30分或高于85分，也不再次触发自动复议。
- 三位专家全部提交后即复议完成，不设管理员终审节点。管理员负责分配和异常管理。

### 4.4 邮件公示流程

14. 系统在次月生成最终评分公示邮件草稿。
15. 六步骤管理员核对公示内容并填写/确认收件范围。
16. 管理员确认后系统发送公示邮件，并记录确认人、收件范围、邮件内容、发送时间和发送结果。
17. 邮件内容至少包括投稿名称、投稿人/部门、最终分数和获奖信息。

### 4.5 投稿状态

以下按第13.2节推荐方案统一状态定义；新增的人工评分状态及相关操作边界待业务确认。“评分方式”和“处理阶段”作为独立字段，不再以“评分完毕（人工兜底）”建立另一主状态。

| 状态           | 进入条件                                                             | 主要后续状态                         |
| -------------- | -------------------------------------------------------------------- | ------------------------------------ |
| 审核中         | 首次提交或退回后重新提交；包括待管理员补齐审核人的情况。             | 评分中、退回修改                     |
| 退回修改       | 直属上级退回，或评分材料需更换并经管理员退回重新审核。               | 审核中                               |
| 评分中         | 审核通过并启动AI评分；自动重试或保存恢复期间保持该状态。             | 评分完毕、评分复议中、评分失败       |
| 评分失败       | 不可自动恢复的问题导致暂停，或自动/手动尝试失败并需管理员处理。      | 评分中、专家人工评分中、退回修改     |
| 专家人工评分中 | AI失败满足兜底条件，管理员启动人工评分；包括待分配和专家处理中。     | 评分完毕                             |
| 评分完毕       | AI有效总分在30至85分之间，或三位专家人工兜底完成。评分方式区分二者。 | 完成；仅常规AI评分允许进入评分复议中 |
| 评分复议中     | 用户异议或极端分数自动复议已创建；包括待分配和专家处理中。           | 复议完成                             |
| 复议完成       | 三位有效专家完成逐项复议，系统已计算结果并设置确认截止时间。         | 完成                                 |
| 完成           | 有权人员确认结果，或复议结果按三个工作日规则自动确认。               | 终态；业务纠错使用独立更正流程       |

人工兜底结果不开放异议、不再次触发高低分复议；普通AI评分及人工兜底的“评分完毕”推荐不设置自动确认，复议完成的超时规则见第13.3节。

### 5.2 直属上级审核

- 待办派发给报告撰写人/投稿人的直属上级。
- 上级需核对报告真实性、完整性、规范性及与六步骤要求的符合度。
- 审核通过或退回均记录处理人、时间和意见；退回意见必填。
- 直属上级关系缺失时系统提示管理员处理，不能静默丢失待办。

### 5.3 六步骤报告完整性提示

| 步骤     | 提交要求/检查提示                                                                                  |
| -------- | -------------------------------------------------------------------------------------------------- |
| 任务明确 | 背景介绍、问题点、内外部环境；ABCD任务定义及一句话概括；时间、负责人、预算和预期输出。             |
| 组织执行 | 定职、定责、定任务。                                                                               |
| 方案有效 | 开展思路（差距分析、初始路径、方案升级/选择、最终方案）及汇报机制（阶段、频率/形式、对象、内容）。 |
| 计划清晰 | 计划完整、全面、有逻辑，包含任务名称、DRI、时间节点和输出物；可用计划表/甘特图。                   |

提交页面展示完整性清单供投稿人自查；系统不根据清单自动评判实质质量。

### 5.4 评分标准与AI评分

- 管理员上传并维护正式评分规则文件及讲解材料，支持版本、状态、生效时间、发布人和发布时间管理。
- 结构化评分规则至少包含维度、评分项、权重/分值、分值范围、评分说明、判定条件和证据要求。
- 标准发布前需验证总分、范围、取整精度等配置；新版本发布不得覆盖已引用历史版本。
- AI任务关联投稿文件版本、评分标准版本和任务ID，异步执行并留存开始/结束时间、模型/服务版本、状态及异常信息。
- 评分结果至少包括总分、逐项得分、逐项依据；具备能力时记录PPT页码或证据位置。
- AI完成后通知报告撰写人及实际提交人；AI失败按4.2执行自动重试和管理员处理。
- AI总分&lt;30或&gt;85时直接进入“评分复议中”，自动创建覆盖全部评分项的复议实例并通知管理员，初始处理阶段为“待分配专家”。阈值比较采用正式评分标准规定的汇总及取整规则处理后的AI总分，页面显示须与判断口径一致；30分和85分本身不触发。
- 保存有效AI评分、判断阈值、创建自动复议实例（如适用）和更新投稿状态须在同一事务内完成，避免出现可提前确认的中间状态；通知异步发送并支持失败重试，通知失败不改变已成立的复议。重复回调或任务重试不得创建多个有效复议实例。

### 5.5 投稿人确认与异议

双人操作冲突、异议次数及不同评分方式的操作边界，按第13.1至13.3节推荐方案评审。

- 报告撰写人和实际提交人均可查看评分结果、确认评分或发起异议。
- 上述操作须受投稿状态和评分方式约束。自动复议期间，页面将AI分数标记为“初评分数，待专家复议”，展示待分配专家或专家处理进度，隐藏“确认评分”和“发起异议”入口；服务端同步校验并拒绝确认原AI评分或重复发起异议的请求，不能仅依靠前端隐藏按钮。
- 发起异议时可多选评分项，每项必须填写异议原因；提交后原始评分只读保存。
- 提交人身份、所代表的投稿人身份、操作时间和所选评分项均需记录。
- 人工复议结果开放后三个工作日未确认，系统自动确认并将记录设为完成。

### 5.6 管理员与专家复议工作台

人工兜底任务采用总分模式，不要求逐项评分；本节逐项提交要求适用于异议及自动复议。专家回避、替换和锁定规则见第13.6节。

- 管理员待分配列表显示投稿信息、自动/人工发起原因、总分、复议范围及专家分配状态。
- 管理员为复议分配三位不同专家；可调整分配但需保留变更原因及历史处理记录。
- 专家默认查看待本人处理任务；不得访问未分配任务。
- 专家必须逐项提交处理方式和评论；选择二次评分时校验分值范围。
- 三位专家全部提交后系统按规则计算结果、关闭复议并通知投稿人与实际提交人。

### 5.7 结果公示与邮件

## 10. 验收标准

下列为已有业务验收条目；第13.14节补充带固定编号的边界场景和决策追踪，待对应推荐方案确认后纳入验收。

18. 投稿人或代投稿人可在系统按时提交，记录撰写人、实际提交人和文件版本；超过截止时间不可提交。
19. 直属上级可审核管理范围内投稿；退回须填写原因；重新提交保留历史文件。
20. AI按有效规则版本完成常规评分并保存总分、明细、依据和标准版本。
21. AI有效评分总分按正式标准汇总及取整后低于30或高于85时，投稿直接从“评分中”进入“评分复议中”，自动创建覆盖全部评分项的复议实例并通知管理员分配三位不同专家，初始显示“待分配专家”；30分和85分进入“评分完毕”。极端分数投稿不存在可提前确认的中间状态，报告撰写人及实际提交人均无法通过页面或直接请求确认原AI评分、另行发起异议；页面显示分数与阈值判断口径一致。
22. 可恢复故障或无效输出先自动重试；仍失败管理员可手动触发；再失败可分派三位专家人工评分，系统取三人总分平均，通知报告撰写人/实际提交人确认且不再开放评分异议。
23. 异议复议按评分项保存原因、原分、专家处理及评论；二次评分者平均，不予受理者排除，全员不予受理则沿用原AI分。
24. 三位专家完成后直接通知报告撰写人和实际提交人，不经过管理员终审；三个工作日未确认则自动完成。
    专家复议结果或人工兜底结果即使仍低于30分或高于85分，也不再次触发自动复议。重复AI回调或任务重试不重复创建有效复议实例；通知失败可重试且不影响已成立的复议状态。
25. 每月截止日、年度截止日期和投稿模板可配置或展示。
26. 管理员可以核对公示邮件、填写收件范围并确认发送；邮件展示规定字段，记录发送结果。
27. 投稿、评分、复议、公示及审计资料保存在系统并长期保存。
28. 投稿记录和工作台支持筛选分页，每页默认10条；权限限制正确。
29. 看板只统计已评分投稿，按投稿月份联动且公式正确。
30. 模拟网络超时或AI服务暂时不可用时，系统按配置重试并记录尝试历史；超过上限后通知管理员，不生成正式评分完成通知。
31. 文件无法读取、关键内容无法解析或评分规则缺失/无效时，暂停评分并展示原因及处理建议，通知相应责任人；修复后可重新触发，不进行无效自动重试。
32. AI输出缺少必需项、得分越界、总分汇总不符或引用版本不一致时，不采用为正式评分；按4.2.1记录并处理。
33. AI已生成有效结果但保存失败时，优先恢复保存；恢复后只产生一份正式结果及对应通知，持续失败通知管理员。
34. 可正常读取的低质量或缺项报告按规则评分；无法读取的内容不得直接按缺项扣分。低于30分或高于85分的有效评分触发复议，30分和85分不触发；仅缺少可选页码或证据位置时不判定评分失败。

## 13. 歧义与边界问题的推荐方案（待业务确认）

本章为2026年10月29日的产品建议，不将推荐值视为业务已经确认的事实。DEC为决策编号，AC为对应验收场景编号；本章所有DEC初始状态均为“待业务确认”。业务确认时记录确认人、日期、结论和变更原因；与既有确认规则不同的建议须明确批准后才能替换原规则。金额、正式评分内容、专家名单及真实资源由业务提供，不生成虚构业务资料。

### 13.1 身份、代投与数据权限（DEC-01）

**疑问：** 谁拥有投稿、谁可编辑、代投是否受托、调岗后权限如何变化，以及多个身份叠加时怎样授权。

**推荐方案：**

- 一份投稿只关联一位报告撰写人；实际提交人由登录账号生成且不可手工冒填。汇报人是报告展示字段，不因被填写而获得权限。首次提交记录实际提交人，后续每批提交另记操作者；不以最近一次编辑者覆盖原提交人。
- 允许在提交页选择在职撰写人并声明已受委托；首次提交同步通知撰写人。推荐本期不新增代投预审批；撰写人可举报未经授权的代投，由管理员核实、暂停相关待办并启动纠错，不直接删除记录。代投授权证明可作为附件留存。
- 撰写人与实际提交人均能查看记录、确认评分、发起异议和确认复议结果；在“退回修改”时均能编辑、上传及重提。首次提交后撰写人、实际提交人、所属周期和归属部门锁定，身份错误由管理员走更正流程，不通过普通编辑转移记录归属。
- 部门和直属上级以撰写人组织关系为准，首次提交保存组织快照，用于历史展示及统计；每次重提重新解析审核人并留存本轮关系。调岗不追溯改变历史部门，也不自动转移进行中的审核任务；管理员因离职、调岗等原因转派并填写原因。
- 所有身份均须为有效账号。停用账号立即失去访问权；历史姓名与操作记录保留。可由另一有效参与者继续处理；两人均不可用时管理员指定承接人并留痕，原参与者信息不覆盖，被替代账号不再具备操作权。
- 直属上级仅处理明确派发给自己的待审核记录，并查看本人处理过的审核批次及其必要材料，不因角色自动访问所有部门投稿。专家只访问当前有效分配的任务；提交后可查本人处理记录，任务被撤销后失去材料访问权。
- 管理员不能直接代替专家给分、覆写AI分或替代投稿人常规确认。多角色授权按有效记录关系计算，仍受自审回避等限制约束；管理员和专家角色显式分配给指定用户，可在管理页面查看、撤销，不默认授予所有员工。
- 门户已发布内容对登录员工开放；投稿原文件、评分详情和看板明细不因门户公开而公开。获奖案例须单独发布，管理员核实其展示授权。

| 操作             | 撰写人/实际提交人    | 直属上级               | 专家                       | 管理员                       | 系统               |
| ---------------- | -------------------- | ---------------------- | -------------------------- | ---------------------------- | ------------------ |
| 查看原投稿及评分 | 本人参与记录         | 本人审核批次所需内容   | 当前分配任务所需内容       | 全量                         | 按任务最小范围     |
| 编辑及重提       | 仅退回修改且符合期限 | 不允许                 | 不允许                     | 授权补交、纠错，不代改原文   | 不允许             |
| 审核通过/退回    | 不允许自审           | 仅当前派发且无利益冲突 | 不允许                     | 仅经正式转派且符合回避条件   | 不允许             |
| 确认及异议       | 按状态和评分方式     | 不因审核角色获权       | 不因专家角色获权           | 不因管理角色获权             | 仅复议超时确认     |
| 提交专家评分     | 不允许评审本人投稿   | 不评审本人审核过的投稿 | 当前有效分配且符合回避规则 | 不因管理角色获权             | 计算，不产生专家分 |

服务端对列表、详情、附件下载、导出、聚合及所有写操作分别校验；前端隐藏入口不能替代权限控制。

### 13.2 主状态、评分方式与恢复路径（DEC-02）

**疑问：** 人工评分状态缺失，“评分完毕”存在两种定义，任务错误与业务状态容易混用。

**推荐方案：** 主状态采用第4.5节；另设评分方式“AI初评/AI失败人工兜底”，以及复议原因“用户异议/AI极端分数”。专家任务处理阶段使用“待分配/处理中/已完成”，AI尝试状态使用“排队/执行/待重试/成功/失败/已失效”。这些阶段不新增为投稿主状态。

| 当前状态       | 允许的主要操作                                     | 必要限制与恢复                                             |
| -------------- | -------------------------------------------------- | ---------------------------------------------------------- |
| 审核中         | 审核人通过或退回；管理员补齐、转派审核人           | 投稿人只读；审核人缺失保留此状态并显示待补齐               |
| 退回修改       | 参与人编辑重提；管理员授权延期                     | 重提生成提交批次；旧审核待办及旧编辑版本失效               |
| 评分中         | 系统执行、重试、恢复保存                           | 不允许同时启动人工评分；过期回调不能落为正式结果           |
| 评分失败       | 修复后重触发；符合条件转人工；文件需更换时退回修改 | 单纯技术修复不改变材料；更换PPT必须重新审核                |
| 专家人工评分中 | 管理员分配、调整专家；专家提交总分及意见           | 转人工时关闭旧AI任务，迟到AI结果仅留档；三人有效提交后出分 |
| 评分完毕       | 参与人确认；仅AI初评允许一次异议                   | 人工兜底不允许异议或再触发极端分数复议                     |
| 评分复议中     | 管理员分配；专家逐项处理                           | 投稿人只读，不能确认AI原分或追加异议                       |
| 复议完成       | 参与人确认；系统到期自动确认                       | 不接受第二轮异议，不允许管理员常规终审                     |
| 完成           | 查看、按权限公示和归档                             | 不直接重开、改分或删除，错误通过DEC-10更正                 |

推荐本期不提供常规撤稿、重复投稿合并、任意状态回退或删除入口。误投由管理员按独立纠错流程标为“已作废”，作为有效性标记保留原状态与全部历史；关闭待办并排除统计和公示。管理员不得借异常操作绕过审核或评分。

### 13.3 确认、异议、并发与三个工作日（DEC-03）

**疑问：** 两位参与者操作冲突、能否多轮异议、人工兜底是否超时完成，以及工作日如何计时。

**推荐方案：**

- 撰写人或实际提交人任一人确认即可，不要求双人确认。确认前明确提示“确认后关闭本次异议入口”；发起异议前提示须一次选择全部异议项。
- 每份正常评审最多一轮用户异议；多项合并提交，原因逐项必填。提交后不允许追加、撤销或再次发起；极端分数自动复议已经覆盖全部评分项，不再接受平行异议。业务纠错不计为新的用户异议轮次。
- 确认、异议、专家替换和提交等写操作使用记录版本和状态条件校验。并发冲突时第一笔成功提交的合法事务生效，后续请求被拒绝并刷新最新状态；草稿尚未提交不锁定他人的操作。
- 只有“复议完成”自动确认；AI普通出分和人工兜底的“评分完毕”不自动确认，推荐待确认满三个工作日提醒，此后每三个工作日提醒一次并在管理员列表标示，不由管理员代确认。
- 复议完成时锁定公司工作日历版本及截止时间。推荐采用公司时区Asia/Shanghai；完成当天不计，从下一工作日算起，到第三个工作日23:59:59截止，调休以公司日历为准。例如周五完成、下周无调休或假日，截止为下周三23:59:59。记录实际完成时刻、日历版本、截止时刻、确认方式及操作者。
- 工作日历未配置或未来日期覆盖不足时仍可查看并手动确认，但不能推算自动截止或执行自动确认，通知管理员补齐；补齐后按原完成时间计算，如截止已过，则给予新的三个工作日窗口并记录延期原因，避免补配置后立即结案。
- 自动确认在截止之后执行，定时任务延迟不改截止时间；执行前再次校验状态，手动确认与自动任务不能重复结案。推荐确认通知未成功送达任一有效参与者站内收件箱时暂停自动结案并告警，恢复送达后至少给予三个工作日，再记录新截止；邮件失败但站内通知成功不阻断。

### 13.4 投稿周期、退回重提与补交（DEC-04）

**疑问：** 月度与年度期限关系、历史月份选择、月底退回如何继续，以及逾期补交入口遗漏。

**推荐方案：**

- 投稿必须选择一个明确周期，类型为“月度常规”或“年度活动”，每份记录只从属于一个周期；月份用于归档统计，不因年度活动覆盖月度记录而重新计数。同一记录可被年度评优活动引用，但不复制为新的投稿数量。
- 月度首次提交截止为对应月最后一天23:59:59，公司时区统一采用Asia/Shanghai，页面明确展示。年度活动有独立开放、截止时间，由管理员按通知配置并发布；不同时叠加两个不同截止条件。
- 仅可首次提交到当前开放周期；历史月份默认不可选。截止校验以服务端成功受理提交事务的时间为准，上传完成不代表已经提交。截止前上传、截止后点击提交按逾期处理；网络重试若带相同操作标识，返回已成功提交的记录。
- 推荐区分“首次投稿截止”和“退回修改截止”：首次按时投稿即保留资格，退回后允许跨月重提，默认自每次退回次日起五个工作日内完成。页面显示该记录独立修改截止，管理员可对单条延期并填写原因；已过修改期限的记录保持退回修改，等待授权，不静默关闭或作废。
- 管理员提供“补交/延期授权”页面，限定人员、周期、投稿记录（如有）、有效截止及原因。首次补交授权默认仅允许创建一份投稿，成功使用后失效；重提延期只影响指定记录。补交仍走上级审核与后续流程，不直接改成已评分。
- 周期发布后修改截止须留痕并通知受影响人员，不追溯否定已受理投稿；年度周期、授权补交、退回重提均保存实际提交时间与原归属周期。

### 13.5 标准版本、总分算法及有效结果（DEC-05）

**疑问：** 版本何时锁定、重试是否换标准、无标准如何恢复，以及精度和人工总分如何一致。

**推荐方案：**

- 上级审核通过时，锁定当时适用的已发布且生效的评分标准、当前提交批次及文件版本。适用范围至少包括周期类型和生效区间；同一范围不允许生效区间重叠，不能按查询顺序任意取一个版本。
- AI重试、人工兜底、专家复议均沿用本轮锁定版本；新标准发布不改变历史任务。退回重提经再次审核通过后属于新一轮评审，按该次通过时锁定版本，旧轮次和结果全部保留并标为已失效。
- 审核通过时无有效标准，保存审核结论和通过时间，投稿进入评分失败并标记“待评分标准”。管理员补发适用于该审核时间的版本并说明补发原因，经显式绑定后启动；不得静默套用后续新标准。补发版本不重算其他历史投稿。
- 标准推荐统一为100分制，使30、60、85分阈值具有固定含义；如正式规则不是100分制，必须先确定归一化公式及阈值映射并重新评审，禁止直接套用阈值。
- 每项必须明确采用“分值相加”或“按权重换算”的单一算法，不能同时加权两次。保留专家原始输入与计算中间精度，仅在规则指定阶段取整；推荐正式总分四舍五入至两位小数。最终精度以正式规则确认值为准，发布前必须配置完整；AI阈值比较与页面显示均使用同一正式总分。
- 非复议项沿用原AI分；复议项使用有效专家二次分平均或全员不受理时沿用原分，再按锁定规则汇总。人工兜底三人直接提交0至100范围内总分及必填理由，按三人平均后采用同一总分精度，不伪造逐项明细。
- 一轮评审最多一份有效AI评分；验证文件版本、任务轮次、明细完整性、范围和汇总一致性后才能入账。过期回调、重复回调和已转人工后的AI结果只留审计，不替换当前有效结果。
- 技术层面的存储恢复不重新调用AI。必须改变文件字节或影响评分含义的规则才能修复时，启动新批次/纠错轮次及必要审核，禁止原位修改已引用文件或标准。

### 13.6 专家回避、替换、处理范围与时限（DEC-06）

**疑问：** 自动复议是否允许不予受理、专家能否看其他分数、替换后哪些评分有效，以及超时怎样处理。

**推荐方案：**

- 三个专家席位分别绑定三位不同且有效的专家；排除本投稿撰写人、实际提交人和本轮已参与审核的人。管理员若与该投稿有上述关系，由另一管理员处理专家分配及公示，系统展示冲突并阻止本人操作。
- 异议复议与极端分数自动复议均允许逐项“二次评分”或“不予受理”，后者必须说明原因；自动复议仅差在覆盖全部评分项。人工兜底只能提交总分及理由，不允许以“不予受理”替代评分，无法处理须申请替换。
- 专家可见PPT、锁定规则、原AI分及依据、异议原因，但在提交前不展示其他专家分数及评论；投稿参与人在三人全部完成前不查看单个专家尚在处理中的意见。管理员可查看进度，任务完成后查看完整结论。
- 专家可保存个人草稿；最终提交必须一次覆盖全部应评项，提交后锁定且不可直接修改。人工兜底须校验总分和理由。
- 推荐只允许常规替换尚未提交的席位，需填写原因；旧分配立即撤销访问和提交权限，新分配不继承旧草稿。已提交席位因回避、误派等必须替换时，走异常纠错审批，旧分保留并标为无效，新专家重新独立提交；结果只取三个当前有效席位，不混算四人或更多人。
- 三人完成后禁止普通替换和改分；走DEC-10结果更正。替换与原专家提交并发时，使用同一分配版本校验，不能同时接受撤销和提交。
- 推荐专家处理期限为分配后五个工作日，第三个工作日首次提醒，到期后通知管理员，此后每两个工作日提醒一次；参数可配置。无专家提交不得自动给分、以零分替代或自动结案；替换后为新专家重新计算期限并保留总等待时长。

### 13.7 AI重试策略与评分质量验收（DEC-07）

**疑问：** 自动重试参数、如何避免长期卡住，以及怎样验证AI评分可用于实际业务。

**推荐方案：**

- 可恢复故障推荐首次失败后自动重试两次，间隔1分钟、5分钟；首次调用加重试最多三次。单次任务推荐10分钟超时，可按文件规模配置。限流优先遵守服务返回的等待时间，并设最大等待时间；不可恢复问题按4.2.1处理，不机械重试。
- 达到上限后进入评分失败并通知管理员；管理员每次手动触发须填写原因，不允许并行运行。一次手动尝试仍因服务或输出问题失败且材料、标准可正常使用时，即可选择人工兜底；不要求无限手动重试。
- 评分中超过任务超时及恢复窗口必须被巡检发现并显示原因；转换人工时使旧任务失效，保留全部历史。
- 模型服务、提示词、解析程序、文件、标准版本均记录版本或摘要。PPT内任何要求改分、忽略评分规则或执行外部指令的文字均作为待评材料，不作为系统指令；评分过程不执行报告中的链接指令或宏，不向未批准的服务传输材料。
- 上线前由业务准备推荐不少于30份脱敏报告，覆盖不同部门、分段、图表/图片型PPT、缺项及解析异常，并由三位专家独立评定后形成业务认可的参考分与争议说明。
- 推荐质量门槛：正常可读样本有效结果率至少95%；与参考总分的平均绝对误差不超过5分，至少90%的报告绝对偏差不超过10分；抽检逐项依据不得引用材料中不存在的事实；缺失依据、越界或算法错误不得通过有效性校验。门槛及样本规模待业务批准，不以成功返回JSON替代质量验收。
- 正常样本选至少10份各独立运行三次，推荐同份总分最大差不超过5分，波动超限或跨越30/60/85阈值的样本逐一分析。解析失败必须明确报错，不能用低分掩盖。
- 模型、提示词、解析程序或正式规则变更后在同一参考集回归，保存结果并经业务批准再切换；不因此批量重评历史投稿。

### 13.8 分数定义、看板与可见范围（DEC-08）

**疑问：** 已评分如何定义、复议中用哪个分、按谁的部门统计、榜单同分和零数据怎样展示。

**推荐方案：**

| 分数名称   | 定义                                                         | 使用场景                                         |
| ---------- | ------------------------------------------------------------ | ------------------------------------------------ |
| 原始AI分   | 有效AI初评结果，不受复议修改                                 | 原始证据、异议对照及极端分数判断；人工兜底无此值 |
| 当前有效分 | 常规AI出分取AI分；复议完成取复议分；人工兜底完成取三人平均分 | 列表和实时看板，必须显示是否待确认               |
| 最终确认分 | 投稿进入完成时冻结的当前有效分                               | 正式公示、获奖记录和归档；更正另建版本           |

- 看板“已评分”推荐只纳入当前有效且主状态为评分完毕、复议完成、完成的投稿；评分复议中暂不纳入，避免将可能被修改的AI初评分作为当前结论。专家人工评分中、评分失败和已作废记录均排除。此项是对原“已评分”的具体化建议，须业务确认。
- “总投稿”保留原指标但加说明“已评分份数”，另展示“待评分/复议中份数”辅助理解，避免误认为全部提交量。复议完成但未确认可进入实时看板，邮件公示必须使用最终确认分。
- 每份投稿只计一次；按原投稿月份筛选，按首次提交的归属部门快照统计。跨月完成后更新原月份看板，不迁到评分发生月。保存统计生成时间，实时看板不等同于历史公示快照。
- 平均分使用未额外展示取整的当前有效总分计算，最后展示两位小数；通过率按正式总分大于等于60判断，百分比展示两位小数。零份时总数为0、平均分与通过率为“—”，榜单为空。
- Top10同分时按首次提交时间升序、记录ID升序稳定排序，最多10份；部门均分同分时依次按投稿数降序、部门ID升序排序。
- 员工及代投人的看板仅计算本人有权访问的记录；上级仅计算其有权查看的审核记录；管理员可看全量。专家角色本身不开放部门看板。未经额外授权，不展示其他部门姓名、报告名或排名；部门汇总不能从无权记录推算。需要全员公司榜单时另设显式发布范围及业务批准，不默认扩大原文件权限。

### 13.9 公示批次、获奖信息与发送安全（DEC-09）

**疑问：** 次月具体哪天、未结案投稿怎么公示、修改草稿是否重新确认、发送结果不明能否重发。

**推荐方案：**

- 推荐在次月第一个工作日09:00为上月投稿生成邮件草稿，时区与公司工作日历统一；生成时间可配置。仅包含有效、已完成且未在该公示类型成功公示的最终确认结果。
- 同期另列尚未完成的投稿数量供管理员跟进，不在公示正文披露未确认分数。未结案记录完成后生成补充公示草稿，仍归原投稿月份；没有可公示记录时只提示管理员，不发空邮件。
- 获奖由管理员维护，记录奖项、等级、年度/月份、关联投稿和维护人；本期不根据分数自动发奖或发奖金。“未获奖/待评定/已获奖”须明确，禁止留空导致歧义；评分结果可先公示并写明待评定，后续奖励名单可另行公示。
- 草稿生成时形成明细快照，确认时再次校验有效性、分数版本及获奖信息。正文、名单、模板、附件或收件范围任一变化均使原确认失效，须重新确认；已发送邮件不可覆盖编辑。
- 推荐收件人限定公司内部有效地址或内部邮件组，逐次展示明确名单或可解析的群组及人数，由管理员确认；外部地址本期禁止。群组成员无法核实范围时阻止确认。审批展示实际披露字段与收件范围，不因邮件接收权授予原文件访问权。
- 邮件草稿、待确认、已确认待发送、发送中、部分成功、成功、失败、结果待核实分别记录；以公示批次、内容版本、收件人为投递唯一键。明确失败可重试，仅补发失败收件人；服务端已接收但回执不明时先查投递状态，不能盲目重发。邮件服务不支持状态核实时交管理员核实后决定重发并留痕。
- 内容、收件范围及确认均冻结后发送；发送前如已批准的内容版本失效，则取消待发送并要求重新审核。发送之后发生业务纠错，使用更正公示引用原邮件，不改历史邮件。

### 13.10 错误更正、误投与管理员操作边界（DEC-10）

**疑问：** 完成后发现错误如何处理，既保持历史不可覆盖，又避免系统永远无法纠错。

**推荐方案：** 提供独立“异常更正申请”，记录原记录、原因、证据、影响范围和拟采取动作；由另一位授权管理员批准，申请人与批准人不能相同。缺少第二管理员时保持待处理并告警，不绕过审批。

- 名称等不影响评分的元数据错误：新增更正版本，保留原值，检查对公示及统计的影响。
- 材料、身份、规则或专家有效性错误：批准后使相关结果失效，关闭旧待办，冻结统计及未发送公示的引用，创建关联的更正评审轮次，经必要审核后重新评分；专家更换仍须满足三位有效专家要求。管理员不能自行输入“修正后分数”。
- 误投或未经授权代投：核实后可作废，保留资料及理由，参与者收到通知。有效性控制与原流程状态分开，所有回调及待办操作都检查有效性。
- 已公示的记录更正：历史邮件保持原样，更正后创建更正公示，记录原、新结果及变更原因；新的最终确认分经原确认机制成立后才可公示。
- 更正流程仅用于事实或程序错误，不作为第二轮主观评分异议通道。全部动作可审计，并提供受影响投稿、统计及公示清单。

### 13.11 文件、通知、门户与易用性（DEC-11）

**疑问：** 文件数量和限制未定、通知清单未完整落地、门户发布及关闭滑窗行为缺失。

**推荐方案：**

- 本期每批提交一份主报告，推荐仅接收.pptx、最大100MB；原有.ppt须先转换，转换前保留原稿留档能力另行评估。该默认值需与公司文件规范及业务存量核实后批准；上线前管理员可配置格式与大小，但不得超过安全平台支持范围。
- 上传成功且安全检查通过后方可正式提交；预览/解析失败与文件安全失败分开提示。图像型PPT如解析服务支持则启用OCR，不支持时明确告警并协调可读材料，不按空白页扣分。预览暂不可用时，有权人员可下载原文件；不得生成永久公开附件地址。
- 每次重提建立新的提交批次；未换PPT时可引用同一不可变文件，但建立新的批次文件版本关系并记录“内容未变”，不伪造上传行为。模板在首次提交时记录版本；模板更新不追溯拒收已提交或退回重提的记录，仅提示采用最新版。
- 滑窗必填校验、上传进度、失败恢复及提交中防重复均需实现；关闭有未保存内容时提示确认。推荐本期不做跨设备草稿，关闭确认后清除未提交表单，孤立上传文件按独立清理策略处理，已提交文件不受影响。
- 通知采用“站内通知为必需，邮件为可配置补充”，不依赖OA主流程。审核待办发当前审核人；退回、出分、复议完成和确认结果发两个参与者并按账号去重；待分配、失败和逾期发管理员；专家任务仅发当前有效专家。
- 通知保存事件、对象、接收人、渠道、投递状态、重试及阅读记录，均提供带权限校验的记录入口。推荐失败后1、5、30分钟重试，耗尽告警；刷新待办不能重复生成通知，撤销任务同步失效旧入口。
- 介绍、案例、激励、课程、工具采用草稿/已发布/已下架；员工只读已发布内容，管理员预览后发布并留存版本。初始案例需真实附件或链接，缺失时不显示伪下载入口。外链标明目标平台，资源失效可下架；课程本期仅跳转，不同步学习进度。
- 关键管理页面同时包含投稿周期/补交、评分规则、专家池/分配、AI异常任务、公示及获奖信息、模板/门户、权限与审计、工作日历与运行参数；不以空配置入口代替真实可操作管理功能。

### 13.13 非功能指标与上线责任（DEC-13）

**疑问：** “按公司标准”“长期保存”“兼容办公浏览器”缺少可验收基准。

**推荐方案：** 以下数值为首版容量和运行目标建议，须产品、技术、运维批准；如公司标准更严格则采用更严格标准，并在上线清单记录具体值。

- 按每月1000份、单文件上限100MB、100名并发在线用户开展容量评估；普通列表及元数据详情接口P95不超过2秒，排除附件下载、PPT预览和AI处理耗时，测试使用至少10000份历史记录。AI吞吐与费用上限另按服务配额压测，排队时展示进度，禁止长期无状态等待。
- 桌面验收覆盖公司批准的Chrome和Edge当前及上一主版本，基准分辨率1366×768；支持键盘访问关键表单、明确错误定位、空态、无权限、加载及失败重试状态。移动端本期以查看和通知跳转可用为目标，不承诺完整PPT评审体验。
- 投稿业务及审计长期保存，不按三年自动删除；备份同时覆盖数据库与文件及其版本引用。推荐恢复点目标24小时、恢复时间目标8小时，每季度进行一次数据库及文件联合恢复演练，记录成功率和差异；长期保留不代表在线热存储永久无限扩展。
- 归档数据仍能按权限查询和恢复原文件；技术可清理未提交孤立文件和无业务价值临时缓存，不得借清理删除投稿历史、正式评分或审计证据。
- 监控AI排队/超时、评分失败、未分配专家、通知失败、自动确认滞后、邮件待核实、存储容量及备份失败；每类有管理员可见状态、责任人和恢复动作。日志不得记录密钥、永久下载凭证或无必要的PPT全文。
- 业务负责人确认DEC-01至DEC-11涉及的业务决策、正式评分标准及参考集；产品负责人组织验收追踪；技术负责人确认一致性、服务集成和性能；运维负责人确认日历维护、邮件域、告警、备份和恢复。未确认的规则不得由研发静默选值上线。
